# health

Одна команда: жива ли машина.

Показывает то, что иначе проверяется руками по десять минут —
сервисы, диск, свежесть бэкапов, карантин синка, кит, заслоны
Telegram, права на ключи, конфиг агентов.

```
health            коротко, без сети
health -v         подробно, плюс проверка порта сервера
health --no-color
```

Код возврата: `0` — всё хорошо, `1` — есть предупреждения, `2` — есть
поломки. Годится для проверки в скрипте.

```
$ health
    ОК    сервис tg-logbook      pid 3526, жив 7 мин
    ОК    бэкапы сессий          6 шт, свежий 2 мин назад (11.0 МБ)
    ОК    снимок читается        11 сессий в базе
    ОК    карантин md            пусто, всё уехало
   ВНИМ   ключ к серверу         права 0o644 — ssh отвергнет
  СТОП:  1 поломка, 1 предупреждение
```

## Что проверяется

| Что | Как |
|---|---|
| сервисы runit | `sv status` плюс `supervise/pid` и `/proc` |
| падение по кругу | счётчик перезапусков в выводе `sv status` |
| подмена pid | имя сервиса ищется в самом процессе **и в его родителях** |
| диск | свободное место и заполнение, отдельно система и дома |
| бэкапы | свежесть последнего снимка, число, `integrity_check`, наличие сессий |
| карантин `md-unsent` | любой файл там означает, что синк его не увёз |
| кит | возраст `void-kit.7z` |
| Telegram | токен заполнен, права 600, `armed`, `PAUSE` |
| ключ к серверу | права на `~/.ssh/dima_server` |
| конфиг opencode | модель по умолчанию, число агентов и навыков |

## Чего скрипт не делает

Ничего не чинит, ничего не отправляет, сеть по умолчанию не трогает.
Только читает. Проверка Telegram — по конфигу, без обращения к Bot API:
иначе `health` сам съедал бы лимит отправок, который сам же и сторожит.

## Почему проверка pid идёт вверх по родителям

Run-скрипт, который держит трап, не может делать `exec` — иначе
шелл заменится и трап пропадёт. Поэтому в `cmdline` остаётся
`/bin/sh ./run`, без имени сервиса. Имя живёт в родителе:
`runsv autosync-dima`. Проверка только самого процесса давала ложное
срабатывание на живом `autosync-dima`.

## Тесты

```
python3 tests/test_health.py
```

18 тестов. Проверяют не то, что скрипт запускается, а то, что он
ловит поломку: мёртвый сервис, удалённый каталог, файл в карантине,
битый и пустой снимок, протухшие бэкапы, права, пустой токен,
исчезнувший кит. Плюс контрольный случай — чистая машина обязана
проходить. Скрипт, который всегда говорит «всё живо», хуже
отсутствия скрипта.

## Установка

```
install -Dm755 bin/health ~/.local/bin/health
```
